1. 背景与目标

小型实验室的小鼠管理普遍依赖纸质笼卡 + Excel：研究生换笼时手抄笼号，繁育对的合笼、断乳日期记在个人备忘录里，基因型鉴定结果以文件名混乱的 PDF 散落在群里。可观察的后果是：找不到某只鼠的父本母本、错过断乳日龄导致同笼打架、伦理年审时花数天从 Excel 反推实际用鼠数量。

本产品面向单 PI 课题组（1 名 PI、数名研究生/博士后、共享的动物房管理员），提供一个以小鼠个体档案为中心、以笼位视图为工作台、以扫码为现场操作入口的轻量管理系统。

目标（可观察表述）：

  • 任意一只在养小鼠，10 秒内可从笼位图或扫码定位到其档案、谱系和所属实验计划；
  • 每一窝仔鼠在断乳日龄到达前自动生成提醒，不出现"靠人脑记"的环节；
  • 任意时间点，系统可按伦理编号导出实际用鼠数量与死亡记录（含死因确认状态），无需人工对账；
  • 换笼、分笼、死亡登记等现场操作可在手机浏览器上扫码完成，巡查中发现的死亡可即时快速登记，尸体不因流程等待而滞留笼内。
约束：小团队低预算 —— 单实例部署、单实验室租户，无多机构权限体系；Web 优先，不开发原生 App；扫码依赖手机浏览器摄像头，不要求专用扫码枪。Assumption, TBD

3. 产品模型

3.1 角色与成员（无权限限制）

系统不设权限限制：PI、研究生/博士后、动物房管理员三种角色仅作为身份标识，用于时间线留痕、待办指派与展示口径。所有成员可执行全部操作——建档、换笼、繁育、送检、计划管理、终态登记与撤销、成员与房间笼架结构管理。

产品判断：小课题组全员互信场景下，权限管控的维护成本高于其风险收益。数据安全以全量操作留痕（S-1）作为补偿控制——任何操作可追溯到具体的人与时间，足以支撑内部问责与伦理审计。角色保留的价值在于待办路由（如死亡归因确认通知分配人），而非授权。

3.3 笼位模型

三级结构：房间 Room → 笼架 Rack → 笼位 CagePosition。笼架为行列网格（如 5×6），每个笼位有坐标（R3-C2）。笼位非对象实体，笼子（Cage）才是实体：一个笼子占一个笼位，含若干小鼠，笼卡二维码 = 笼子 ID。笼子可整体移动到空笼位（换笼/腾笼操作），小鼠不可同时属于两个笼子。

产品判断：以"笼"而非"鼠"为扫码主入口 —— 现场 90% 的操作（换笼、观察、记录死亡）以笼为单位发生，鼠级二维码（耳标）仅在需要定位单只时使用。

4. 功能需求

FR-1笼架与笼位看板P0

目的：研究员进入动物房前，在浏览器上即看到所有房间笼位占用、每笼鼠数与待办标记，替代"挨个掀笼卡"。

触发：任何成员打开"笼位"页，选择房间与笼架。

处理规则：

  • 笼位格显示：笼号、在养鼠数；鼠标悬停/点按展开笼详情面板；
  • 笼格颜色语义：空笼 = 白；正常 = 蓝边；有未完成提醒（待断乳/待分笼/待鉴定）= 黄边黄底；
  • 选中空笼位可发起"放入新笼"；选中占用笼可发起"移动笼子到空位"；
  • 笼详情面板列出每只鼠：ID、性别（公蓝/母粉）、日龄、基因型徽标、状态标记。

结果与状态变化：移动笼子即时持久化并写入笼位历史（笼子 X 于 T 时刻从 A1 移至 B4，操作人 Y）。

异常：目标笼位已被占用时移动按钮置灰并提示"该笼位已占用"；笼架无数据时显示空态引导"先创建房间与笼架结构"。

FR-2小鼠个体档案P0

目的：每只鼠一页档案，聚合身份、谱系、鉴定、所属计划与操作历史，是全局检索与扫码跳转的落点。

触发：建档（手动录入 / 从窝次批量生成仔鼠档案）、笼位面板点击鼠 ID、扫码跳转。

处理规则：

  • 手动建档：必填字段见 3.2 表；外购鼠允许填"周龄"反推出生日期并标记 约；
  • 从窝次生成：选择窝次 → 按存栏数（经数量修正后）输入公/母数量 → 批量生成档案，自动继承父母本品系、出生日期=窝次出生日期、初始笼位=繁殖笼；
  • 档案页时间线倒序展示全部事件：换笼、鉴定、配种参与、计划分配、终态（含快速登记死亡的两段留痕，见 FR-8a）；
  • 检索支持 mouse_id 精确、品系/基因型/计划/状态组合筛选。

字段可编辑性：出生日期、性别、来源在存在下游事件（鉴定、繁育）后锁定，可解锁修改（留痕）；终态小鼠档案整体只读。

异常：删除档案仅允许"无任何下游事件且建档 24h 内"的情形，二次确认后执行；其余情况以"淘汰"终态替代删除，保证谱系不断链。

FR-3扫码工作台P0

目的：换笼间里戴手套不方便打字 —— 手机扫笼卡二维码后，三步内完成当日现场操作。

触发：手机浏览器进入"扫码"页调起摄像头；扫出笼 ID 或鼠 ID。

扫出笼子后的操作面板（按频次排序）：

  1. 快速换笼：扫新笼位或从空位列表选择 → 确认；
  2. 观察记录：选择预设项（正常/精神差/打斗受伤/死亡）+ 可选备注；选"死亡"→ 进入 FR-8 登记流程：死因已知时直接选择完整死因枚举；现场无法判断时选用快速登记（初判 + 归因确认，见 FR-8a）；
  3. 产仔登记（繁殖笼专属入口）：输入仔鼠数与出生日期 → 生成窝次；
  4. 查看本笼待办：跳转 FR-6 该笼的未完成提醒。

结果与反馈：每次操作返回绿色成功条并震动一次（Assumption, TBD：目标机型支持浏览器震动 API）；连续扫码模式下成功条 1.5 秒后自动回到摄像头，支持不换页连续处理多笼。

异常：扫出未注册 ID → 提供"以此 ID 现场建档"入口；摄像头不可用（权限拒绝/老旧浏览器）→ 降级为手动输入笼号；网络中断 → 操作进入本地待同步队列并在顶部显示"待同步 N 条"，恢复后自动重传（防换笼间信号死角丢数据）。

FR-4繁育对与窝次谱系P0

目的：谁和谁配、哪天合的笼、仔鼠哪天该断乳、祖代是谁 —— 全部可追，替代研究生个人备忘录。

触发：创建繁育对（选 1 公 + 1~2 母 Assumption, TBD：支持 1 公 2 母合繁）；产仔登记；分笼/结束繁育对。

处理规则：

  • 繁育对要求参与者均为在养、未处于另一"合笼中"繁育对；
  • 产仔登记后生成窝次 L-编号，仔鼠档案按 FR-2 批量生成，谱系自动挂接父母；
  • 1 公 2 母笼内产仔时，母本归属允许标记"不确定"，谱系树中该窝母本显示"母A 或 母B"，待基因型鉴定后可人工确认修正；
  • 谱系视图：以任意鼠为中心，向上两代、向下两代渲染谱系树；点击节点跳转档案；
  • 近交提示：所选公母在谱系树两代内存在共同祖先时，创建繁育对页面显示黄色提示（不阻断，仅提示）。

FR-5基因型鉴定管理P0

目的：把"送检-回收结果-按结果分笼"从 Excel 三张表合并成一条流水线。

流程：从窝次或筛选结果勾选小鼠 → 生成送检批（检测项目如 Cre PCR，系统生成送检清单含鼠 ID 与取样要求）→ 结果回收时逐条录入阳性/阴性/杂合/无效 → 档案基因型更新、谱系同步、"待鉴定"提醒关闭。

处理规则：

  • 结果录入支持按送检清单顺序的键盘速录模式（+/-/±/F 四键）；
  • "无效"结果自动重新挂入该鼠待办"需重新取样鉴定"；
  • 分笼辅助视图：同一窝次按鉴定结果分组列出，勾选目标基因型 → 一键分配新笼并生成换笼操作记录。

FR-7实验计划与伦理编号关联P0

目的：伦理年审时一键回答"这个编号下实际用了多少只鼠、都是谁、怎么处理的"。

触发：PI 创建计划并填写伦理编号与批准上限；成员将小鼠分配至计划。

处理规则：

  • 分配校验：仅在养小鼠可分配；一只小鼠同时只属于一个进行中计划；
  • 实际用鼠数 = 该计划下已进入任一终态的小鼠数（含快速登记的死亡，与安乐死口径一致；死因未确认不阻断计数，报表单列「原因待确认」数量），只读，实时回写；

FR-8安乐死与离群记录（完整登记）P0

目的：终态登记是合规证据链的最后一环，必须"原因必填、操作留痕、数量回写"。本节定义完整登记流程（含完整死因枚举与撤销规则）；现场无法判定死因时的快速登记见 FR-8a。

触发：档案页、扫码工作台、或筛选列表批量选择 → "登记离群"。

处理规则：

  • 三选一终态：已用于实验（安乐死）/ 自然死亡 / 淘汰；
  • 原因必填：预设枚举（实验终点 / 人道终点-发病 / 人道终点-体重下降 / 基因型不符 / 超龄 / 其他-备注必填）；
  • 批量登记时对每只鼠继承同一原因，可逐只修改；
  • 确认弹窗列出将受影响的小鼠清单与所属计划，输入确认文字 确认 后执行；

  • 撤销（当日留痕撤销）：

FR-8a死亡快速登记与归因确认（初判模式）P0

目的：动物福利要求尸体及时移出（登记不能被任何确认流程阻塞），但现场往往无法立即判定死因。本模块提供快速登记（初判）模式，设计原则是「事实与归因分离」：死亡是客观事实 → 登记即生效；死因是实验数据 → 由最了解实验语境的分配人在 48h 内补全。系统不设权限限制，本模式对所有成员开放——选择它的是登记策略，而非身份。

触发与范围：任何成员在扫码工作台（FR-3）或档案页选择「快速登记（初判）」。初判记录的状态同样立即生效；后续补全死因走归因确认闭环。范围仅限「自然死亡」——「已用于实验（安乐死）」与「淘汰」是明确决策，始终走 FR-8 完整登记。

环节规则
